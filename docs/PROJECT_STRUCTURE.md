| `test`, `test:integration`, `test:e2e` | Vitest unit/component, Vitest against Postgres, Playwright |

## Module Responsibilities
- **`src/app/`**: Routing, layouts, `loading.tsx`/`error.tsx`, metadata. A page awaits DTOs from `server/features/*/queries` and passes them to a component. No logic, no SQL, no third-party calls.
- **`src/server/actions/`**: The only door from the UI into the server. Each export is built from a next-safe-action client in `_clients.ts`.
- **`src/server/features/`**: Domain logic split into service (rules), queries (reads), policy (access), schema (input) and dto (output shape).
- **`src/server/{auth,billing,quota,storage,ai,weather,ramadan,importer,realtime,notify,outbox,audit}`**: Cross-cutting infrastructure, each behind a small interface that tests can mock.
- **`src/components/`**: Presentation and interaction only. They hold UI state (open, draft, optimistic) and import **only** `server/actions/*`, `server/**/dto.ts` types and `lib/*`.
- **`src/lib/`**: Pure helpers safe on both sides. Nothing that encodes a business rule, a limit or a price.
- **`config/` + `scripts/` + `drizzle/`**: Plan configuration, operational tasks and schema history. Limits and the catalog live in the DB via seeds, not as constants in code.
